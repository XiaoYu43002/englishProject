---

## 2. 判断这次要不要重装 / 重建

| 变更内容 | 要做什么 |
| --- | --- |
| 只改了 `src/` 页面、组件、样式 | 重新编译或热更新前端即可 |
| 改了 `package.json` / `package-lock.json` | 必须 `npm install`，再编译前端 |
| 改了 `server/` | 重启 Node API |
| 改了 `ocr_service/` 或 `requirements.txt` | 重建/重装 OCR，再重启 |
| 改了 `docker-compose.yml` 或 Dockerfile | `docker compose up --build` |
| 改了 `data/`、词库脚本 | 按需跑词库同步脚本（见第 6 节） |
| 改了原生插件 / `manifest.json` App 配置 | App 端建议重做自定义调试基座 |

## 4. 后端：编译 / 启动

后端分两块：**Node API（8787）** + **RapidOCR（8790）**。可选 **Kokoro TTS（8880）**。

### 方式 A：Docker（推荐）

```bash
cd /home/lihao/zhimi-uniapp

# 若没有 .env，先复制
cp -n .env.example .env

# 重建并启动 ocr + api + kokoro
docker compose up -d   #启动
docker compose up --build -d   # 重建并启动

# 看日志
docker compose logs -f api
# 或
docker compose logs -f ocr
```

停止：

```bash
docker compose down
```

说明：

- `api` 容器挂载当前目录，改完 `server/` 后可直接：

```bash
docker compose restart api
```

- OCR 镜像或 `requirements.txt` 变了，必须 `--build`，不能只 restart。

### 方式 B：本地进程（不用 Docker）

**终端 1 · OCR**

```bash
cd /home/lihao/zhimi-uniapp
# 首次或 requirements 变更时：
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
python -m pip install -r ocr_service/requirements.txt

npm run dev:ocr
# 等价于：python -m uvicorn ocr_service.app:app --host 0.0.0.0 --port 8790
```

**终端 2 · Node API**

本地跑 API 时，把 `.env` 里 OCR 地址改成宿主机，例如：

```env
OCR_SERVICE_URL=http://127.0.0.1:8790
KOKORO_TTS_URL=http://127.0.0.1:8880
VITE_API_BASE_URL=http://127.0.0.1:8787
```

然后：

```bash
cd /home/lihao/zhimi-uniapp
npm run dev:server
# 等价于：node server/index.mjs
```

Node 服务无单独“编译”步骤；改代码后停掉进程再重新 `npm run dev:server`。

### 健康检查

浏览器或 curl：

| 地址 | 含义 |
| --- | --- |
| `http://127.0.0.1:8790/health` | OCR 存活 |
| `http://127.0.0.1:8787/health` | API / 词库 |
| `http://127.0.0.1:8787/api/ocr/status` | API → OCR 代理链路 |

## 5. 前端：编译 / 运行

按你实际调试的端选择。**开发用 `dev:*`，交付/安装包用 `build:*`。**

### 5.1 H5（浏览器）

开发：

```bash
npm run dev:h5
```

访问终端里的地址（常见 `http://localhost:5173`）。

正式构建产物：

```bash
npm run build:h5
# 输出：dist/build/h5
```

### 5.2 微信小程序

开发：

```bash
npm run dev:mp-weixin
```

用微信开发者工具打开：`dist/dev/mp-weixin`。

正式构建：

```bash
npm run build:mp-weixin
# 输出：dist/build/mp-weixin
```

### 5.3 Android / App（HBuilder 调试基座）

开发编译（生成可被基座加载的资源）：

```bash
npm run dev:app
# 输出：dist/dev/app
```

正式构建：

```bash
npm run build:app
# 输出：dist/build/app
```

然后用 **HBuilderX**：

1. 打开本项目根目录。
2. 运行 → 运行到手机或模拟器 → **标准调试基座**（优先）。
3. 若用自定义基座：依赖或原生配置变过之后，先「制作自定义调试基座」再安装运行。
4. 出现白屏 / `vue is not defined` 时：清缓存后强制重编再跑基座。

```bash
npm run dev:app -- --force
```

真机调试若换过 Wi‑Fi / IP，另见：`docs/换网络调试指南.html`。

## 6. 词库相关（仅数据变更时）

一般业务代码更新**不必**跑这些。只有词书 / 词库脚本或 `data/` 变更时才执行：

```bash

npm run sync:wordbooks

# 仅导入（已有 inputs）
npm run import:wordbooks

# 词典构建 / 接入 App（按仓库脚本需要）

```

## 8. 常见问题

| 现象 | 处理 |
| --- | --- |
| `vue is not defined` 白屏（App 基座） | `npm run dev:app -- --force`，换标准基座或重做自定义基座；确认 HBuilderX 与项目 `@dcloudio` 编译器版本接近 |
| 前端请求失败 | 检查 `.env` 的 `VITE_API_BASE_URL` / `PUBLIC_API_BASE_URL`，真机勿用 `127.0.0.1`，改用电脑局域网 IP |
| OCR 超时 / 识别失败 | 确认 8790 健康；Docker 下 `OCR_SERVICE_URL=http://ocr:8790`，本地直连用 `http://127.0.0.1:8790` |
| `npm install` 很慢或失败 | 使用 Node 20/22；必要时清理后重装：`rm -rf node_modules && npm install` |
| Docker 旧容器行为异常 | `docker compose down && docker compose up --build -d` |
