换网络后如何继续真机 / 小程序调试

手机、微信小程序不能访问虚拟机里的 localhost。 换 Wi‑Fi / 热点后，主要改 .env 里的 API 地址，并在 Windows 上重新做端口转发，再重新编译前端。

1. 先搞清三条地址

Windows 局域网 IP

手机实际访问的地址（写进 .env）

PowerShell / CMD：

ipconfig
# 看「无线局域网适配器 WLAN」的 IPv4
# 例如：192.168.43.168
Linux 虚拟机 IP

Docker API 真正跑在这里（写进 portproxy）

虚拟机终端：

hostname -I
# 常见 VMware NAT：192.168.111.128
链路

手机 / 微信 → http://<Windows IP>:8787 → Windows 端口转发 → <虚拟机 IP>:8787 → Docker API 容器

手机与 Windows 必须同一 Wi‑Fi / 同一热点。

2. 只改这一个文件

文件 改哪里 改成什么
/home/lihao/zhimi-uniapp/.env VITE_API_BASE_URL
PUBLIC_API_BASE_URL 		都改成 Windows 当前局域网 IP，端口固定 8787：
http://192.168.x.x:8787
不要改： OCR_SERVICE_URL、KOKORO_TTS_URL（Docker 内部地址，给容器用）。 也不要把真机地址写成 localhost / 127.0.0.1。

示例（.env 里这两行）

# 换成你这次 ipconfig 看到的 Windows WLAN IPv4
VITE_API_BASE_URL=http://192.168.43.168:8787
PUBLIC_API_BASE_URL=http://192.168.43.168:8787

3. 换网络后完整步骤

  1. 查 Windows 新 IP 
    ipconfig

    记下 WLAN（或当前在用网卡）的 IPv4，下面记作 WIN_IP。

  2. 查虚拟机 IP（在 Linux 虚拟机里） 
    hostname -I

    记下类似 192.168.111.128 的地址，下面记作 VM_IP。

  3. 改项目 .env（在虚拟机里编辑） 
    cd /home/lihao/zhimi-uniapp
nano .env
# 或用 Cursor / VS Code 打开 .env
# 只改 VITE_API_BASE_URL 和 PUBLIC_API_BASE_URL 为：
# http://WIN_IP:8787
  4. Windows 管理员 CMD：重建端口转发 
    netsh interface portproxy delete v4tov4 listenaddress=0.0.0.0 listenport=8787

netsh interface portproxy add v4tov4 listenaddress=0.0.0.0 listenport=8787 connectaddress=VM_IP connectport=8787

netsh interface portproxy show all

netsh advfirewall firewall add rule name="Zhimi API 8787" dir=in action=allow protocol=TCP localport=8787

    把上面命令里的 VM_IP 换成真实虚拟机 IP。防火墙规则若已加过，可跳过最后一条。

  5. 虚拟机：确认后端在跑 
    cd /home/lihao/zhimi-uniapp
docker compose up -d
curl -s http://127.0.0.1:8787/health

    应返回带 "ok":true 的 JSON。

  6. 虚拟机：重新编译前端（.env 改了必须重编，旧 dist 里地址是写死的） 
    # 微信小程序
npm run dev:mp-weixin

# App 真机（另开终端）
npm run dev:app

# 可选：H5
npm run dev:h5
  7. 验证链路，再打开调试工具
    • Windows 浏览器：http://WIN_IP:8787/health
    • 手机浏览器（同网）：同上
    • 微信开发者工具：导入 dist/dev/mp-weixin，勾选「不校验合法域名」
    • HBuilderX：导入 dist/dev/app，运行到手机

4. 命令速查（复制用）

A. 虚拟机一键启动后端 + 编译

cd /home/lihao/zhimi-uniapp

# 1）先改好 .env 里的两个 *API_BASE_URL*

# 2）后端
docker compose up -d
curl -s http://127.0.0.1:8787/health

# 3）前端（按需开）
npm run dev:mp-weixin
npm run dev:app

B. Windows 端口转发模板

REM 管理员 CMD；把 192.168.111.128 换成当前 hostname -I 的结果
netsh interface portproxy delete v4tov4 listenaddress=0.0.0.0 listenport=8787
netsh interface portproxy add v4tov4 listenaddress=0.0.0.0 listenport=8787 connectaddress=192.168.111.128 connectport=8787
netsh interface portproxy show all

5. 常见问题

手机打不开 /health

  • 手机和 Windows 是否同一网络
  • portproxy show all 是否指向正确的 VM_IP:8787
  • 虚拟机里 docker compose ps，api 是否 Up
  • Windows 防火墙是否放行 8787

健康检查通了，但 App / 小程序仍请求失败

  • 多半是用了旧编译产物：改 .env 后必须重新跑 dev:mp-weixin / dev:app
  • 微信里确认已勾选「不校验合法域名」
  • 可在编译产物里搜一下是否已是新 IP（如 dist/dev/mp-weixin/config/api.js）

虚拟机 IP 变了（重启 / 改网卡模式）

  • 重新 hostname -I，更新 Windows 的 portproxy connectaddress
  • .env 里仍写 Windows IP，一般不用因虚拟机 IP 变化而改 .env
记住一句话： 手机用的地址写在 .env 的 VITE_API_BASE_URL / PUBLIC_API_BASE_URL； 虚拟机地址只出现在 Windows 的 netsh portproxy 里； 改完 .env 一定要重新 npm run dev:mp-weixin / dev:app。
